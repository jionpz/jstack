原因在 `src/store.js` 的 `load`。它把读文件和 `JSON.parse` 包在同一个 `try` 里，`catch` 之后直接返回空数组 `[]`，不报错也不提示。你把 tasks.json 改坏一个括号后，`JSON.parse` 抛出语法错误，这个异常被吞掉，`load` 把“文件解析失败”当成了“还没有任务”。

接着 `tasknotes add` 在这个空数组上追加新任务，然后调用 `save` 把结果写回同一个文件。`save` 用 `fs.writeFileSync` 整个覆盖 tasks.json，原来那些任务的内容就被只含新任务的数组替换掉了。所以文件里只剩刚加的那一条。

要避免这种情况，`load` 应该只在文件不存在（`ENOENT`）时返回空列表，解析失败时报错退出，不要继续写回。之前的数据除非有备份或者在 git 里，否则已经被覆盖了。
